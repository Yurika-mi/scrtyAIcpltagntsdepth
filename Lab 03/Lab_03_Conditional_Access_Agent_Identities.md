# ラボ 03: Zava エージェント ID の条件付きアクセス

## 概要

Zava の最高情報セキュリティ責任者(CISO)は、レビュー済みおよび承認された AI エージェントのみが企業リソースにアクセスできることを義務付けました。ガバナンスレビュープロセスを経ていないエージェントはすべて自動的にブロックされる必要があります。さらに、エージェント ID がトークン取得動作の異常など、侵害の兆候を示す場合は、手動による介入なしに即座にブロックされる必要があります。

これら両方の制御を Agent Identities の条件付きアクセス(プレビュー)を使用して実装します。Patti Fernandes がサインインログでのポリシー評価の可視化を検証します。このラボは、後続のすべてのセキュリティラボが構築する Zava エージェントガバナンスベースラインを確立します。

Agent Identities の条件付きアクセスは Microsoft Entra ID のプレビュー機能であり、Zero Trust コントロールをエージェントに拡張します。カスタムセキュリティ属性を作成して各 Zava エージェントの承認ステータスを分類し、未承認のエージェント ID が組織リソースにアクセスするのをブロックする条件付きアクセスポリシーを構築し、Entra ID 保護 信号に基づいて危険度が高いエージェント ID をブロックする2番目のポリシーを作成します。ポリシーはまずレポート専用モードで検証されてから、強制に切り替えられます。Patti Fernandes がエージェントサインインイベントを調査して、条件付きアクセスポリシー評価を確認します。

---

## 目的

- エージェント分類用のカスタムセキュリティ属性セットおよび承認ステータス属性を作成する。
- 3つの Zava エージェント ID すべてに承認ステータス属性を割り当てる。
- 未承認のエージェント ID をブロックする条件付きアクセスポリシーを作成する。
- What if ツールを使用してポリシースコープを検証し、タグなしエージェントがブロックされることを確認する。
- ポリシーを強制モードに切り替える。
- 危険度が高いエージェント ID をブロックする2番目の条件付きアクセスポリシーを作成する。
- Patti Fernandes として Zava HR アシスタント を呼び出してエージェントサインインイベントを生成する。
- エージェント ID サインインログで条件付きアクセスポリシー評価を調査する。

## 演習 3: 危険度が高いエージェント ID をブロックする条件付きアクセスポリシーを作成する

### タスク 1: ポリシーを作成し、割り当てを構成する

1. **[条件付きアクセス]** ページで、**[+ 新しいポリシー]** を選択します。

	![](./media/Lab-03-57.png)

2. **[名前]** フィールドに `Zava - 高リスク エージェントの ID をブロックする` と入力します。

3. **[割り当て]** の下で、**[ユーザーまたはエージェント]** の下の **[ユーザーまたはエージェントが選択されていません]** を選択します。

	![](./media/Lab-03-58.png)

4. **[このポリシーは何に適用されますか?]** の下で、**[エージェント]** を選択します。

5. **[対象]** の下で、**[すべてのエージェント ID]** を選択します。

	![](./media/Lab-03-59.png)

6. **[ターゲットリソース]** で、**[ターゲットリソースが選択されていません]** を選択してから、**[すべてのリソース (以前の 'すべてのクラウド アプリ')]** を選択します。

	![](./media/Lab-03-60.png)

7. **[条件]** で、**[0 個の条件が選択されました]** を選択します。その後、**[エージェントリスク]** の下で **[未構成]** を選択します。

	![](./media/Lab-03-61.png)

8. **[エージェントリスク]** パネルで、**[構成]** を **[はい]** に設定します。**[ポリシーを適用するために必要なエージェント リスクのレベルを構成する]** の下で、**[高]** を選択します。**[完了]** を選択して条件を確認します。

	![](./media/Lab-03-62.png)

9. **[アクセス制御]** の下で、**[許可]** の下で、**[アクセスをブロック]** が選択されていることを確認します。

	![](./media/Lab-03-63.png)

10. **[ポリシーを有効にする]** で、**[レポート専用]** を選択します。

    > **注:** このポリシーはレポート専用に設定されています。Entra ID 保護 からのエージェントリスク信号は、リスクレベルが生成される前にアクティブなエージェント使用が時間をかけて必要だためです。新しくプロビジョニングされたラボ環境では、リスク信号はまだ存在しません。レポート専用モードにより、ポリシーを評価して将来のサインイン イベントに対して、アクセスをブロックする前に評価できます。本番環境では、このポリシーはベース ライン リスク信号データが確立されたら、オンに切り替えられます。

11. **[作成]** を選択してポリシーを保存します。

	![](./media/Lab-03-64.png)

13. **[ポリシー]** ページで、**[Zava - 高リスク エージェントの ID をブロックする]** が **[レポート専用]** のステータスで表示されていることを確認します。

## 演習 4: エージェント サインイン イベントを生成し、条件付きアクセス ポリシー評価を調査する

### タスク 1: Zava HR アシスタント を呼び出す

1. 新しい **InPrivate** または **Incognito** ブラウザウィンドウを開きます。

2. 以下のURLを使用して Copilot studio に移動します。

    ```
    https://copilot.microsoft.com
	```

3. **[環境]** タブからの **Patti Fernandes** 認証情報を使用してサインインします。(ユーザーIDとして **<inject key="User 02 UPN"></inject>** を使用でき、リソースタブから一時アクセスパスのユーザーパスワードを使用します。)

4. Microsoft 365 Copilot チャットインターフェースで、ナビゲーションから **[すべてのエージェント]** を選択します。**[Zava HR アシスタント]** を検索して選択します。

	![](./media/Lab-03-65.png)

5. その後、**[追加]** を選択します。

	![](./media/Lab-03-66.png)

6. チャット入力フィールドに、以下を入力します。

 ```
Zava の休暇ポリシーは何ですか?
 ```

7. Zava HR アシスタント が応答するのを待ちます。

	![](./media/Lab-03-67.png)

8. チャット入力フィールドに2番目のメッセージを入力します。

 ```
病気休暇をリクエストするにはどうすればよいですか?
 ```

## まとめ

このラボでは、5つの定義済みガバナンス値を含む **[エージェント承認ステータス]** 属性を持つ **[エージェント属性]** という名前のカスタムセキュリティ属性セットを作成しました。Zava HR アシスタント に **[HR_承認済み]** 承認ステータスを割り当てて、Entra ID に構造化されたエージェント分類モデルを確立しました。すべてのエージェント ID を対象とし、承認された属性値を持つものを除外する **[Zava - 承認されていないエージェント ID をブロックする]** 条件付きアクセスポリシーを作成しました。レポート専用モードでWhat ifツールを使用して、承認されたエージェントがブロックポリシーから正しく除外されることを検証してから、ポリシーを強制モードに切り替えました。Entra ID 保護 エージェントリスク信号を使用して **[Zava - 高リスク エージェントの ID をブロックする]** ポリシーを作成し、リスク信号生成を待機するためにレポート専用に設定しました。Patti Fernandes が Zava HR アシスタント を呼び出してサインインイベントを生成し、エージェントの種類でフィルタされたサービス プリンシパルのサインイン ログでそれらを調査しました。Zava のエージェント ID は ゼロ トラスト 条件付きアクセス制御でガバナンスされるようになりました
